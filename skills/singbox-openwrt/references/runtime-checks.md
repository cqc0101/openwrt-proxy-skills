# 节点切换与连通性验证

## 修改链接

使用 `scripts/node_link.py input.txt output.txt --set fp=chrome` 修改 query；输入和输出应为本地受限文件，不把完整节点链接放到命令行或日志。工具拒绝覆盖已有输出，保留账号编码和 `#fragment`。更新后的链接仍须通过对应引擎校验。

Reality 链接必须显式包含非空 `fp`。`fp=chrome` 与 Dae 全局的 `utls_imitate: chrome_auto` 属于不同配置项，不可互换。`dae validate` 只覆盖配置校验；重载后还要检查目标节点是否被拒绝、代理组是否为空。日志可能保留历史错误，应以本次重载时间及后续探测为界。

## 从客户端验证

在 LAN 客户端运行：

```sh
python scripts/check_path.py --interface 192.0.2.10 --url https://example.com/
```

每次最多 8 个请求，单次最长 30 秒，默认响应大小上限 256 KiB、速率上限 256 KiB/s。保持证书校验，不跟随重定向，不使用环境代理。结果记录请求的接口、实际源地址、目标地址、HTTP 状态、耗时、接收字节及平均速度；超过响应上限或超时应报告未完成，不能当作最大带宽。

`--interface` 不绑定系统 DNS。双网卡时先分别记录默认路由、接口 metric 和 DNS 服务器；Windows 可使用 `Get-NetIPInterface`、`Get-NetRoute`、`Get-DnsClientServerAddress`。再使用 `Resolve-DnsName example.com -Server <路由器LAN地址> -Type A` 取得答案，通过 `--resolve example.com=192.0.2.20` 测试同一地址。该参数仅使用所提供的答案，不证明 DNS 服务器、加密上游或无泄漏；保留查询来源与时间作为单独证据。需比较系统解析和指定路由器解析的实际请求，不能只测试指定 IP 后宣布普通访问正常。

工具先区分本机参数/依赖错误与请求失败。测试临时代理时，先确认进程存活和监听就绪，并做直连对照；通道不可用时，本轮节点结果无效。临时进程只监听回环地址，使用 SSH 隧道；不要开放匿名代理或假定设备安装了 `nohup`。不得随意使用未知的绕过标记，否则可能测试到嵌套代理。

## 判断与回退

- 进程运行、端口监听、节点认证、目标 HTTPS、LAN 转发及 DNS 路径分别报告。`doctor.sh` 的 `healthy` 仅表示未匹配到本地已知问题；`outbound_ok` 仅是路由器 HTTP 可达性，均不证明 LAN 代理健康。
- 测速使用小流量、多次同目标对照，区分首字节时间和传输速度；单次超时不等于节点永久不可用。比较同一客户端、同一参数下的不同接入网络后，才能缩小线路问题范围，不从 Ping 或中间跳无响应直接断言封锁。
- 节点切换只修改引擎配置；不顺带运行网络加固或改变 DNS、防火墙。先备份并记录原配置哈希，在 `/tmp` 生成权限为 600 的候选配置并校验。
- 自动回退必须在替换前启动并收到就绪确认，独立于当前 SSH 会话；回退与确认使用同一互斥机制。恢复失败要保留备份并明确报错。不要通过共享临时 PID 文件盲目杀进程。
- 在新 SSH 连接中核对实际配置哈希、目标节点载入、至少两个目标的 HTTPS、路由器 DNS 结果及普通客户端访问后，才确认保留。失败立即恢复并复查原配置哈希和实际访问；热重载不保证全部长连接无感。
- 自动切换只接纳参数正确且重复实际转发通过的节点。配置冷却时间和连续失败门槛，未验证的节点不进入备用池；延迟低不代表带宽高。不要为满足切换目标而在失败后连续尝试生产配置。
