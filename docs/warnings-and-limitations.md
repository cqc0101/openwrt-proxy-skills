# 使用限制

这些脚本修改代理配置、防火墙、DNS 和内核参数。部署前保存配置和可用的管理入口。当前设备测试范围见 [R2S 报告](../reports/hardware/FINAL-REPORT.md)，历史审计见 [复核记录](audit-2026-11-12.md)。

## 版本与设备

sing-box 模板按 1.13/1.14 字段区分；dae 生成器区分 legacy 与 modern。静态检查不能替代目标二进制的 `sing-box check` 或 `dae validate -c`。版本升级后重新校验，未知版本不视为已兼容。

dae 需要相应内核 eBPF、BTF 和接口支持；sing-box TUN 需要 `/dev/net/tun`。探测到文件或命令存在，只能说明具备部分条件。R2S 测试没有完成 TUN、物理 LAN 透明转发和公网 IPv6 业务验证。

## 配置与恢复

先把候选配置写入 `/tmp`，限制文件权限，经原生校验后备份并替换。网络脚本将恢复状态保存在 `/etc/proxy-skills-network`，使用设备锁防止并发写入。断线后的定时恢复和重启恢复已在 R2S 测试；持续的防火墙或服务故障仍可能需要人工处理。

`--confirm` 撤销自动恢复计时，保留手动回滚基线。确认前检查 SSH、DNS 和客户端实际流量；不要只看命令返回码。外部工具修改已接管文件后，脚本会拒绝覆盖并保留快照，需先核对冲突。

原生 dae 脚本与 daed 面板应选用一个配置管理入口，避免配置被另一方重载覆盖。

## 订阅与内存

标准库 YAML 降级解析器只支持部分 Clash 语法，复杂锚点和合并建议使用 PyYAML。解析成功后仍需检查节点是否完整。

订阅默认最多保留 15 个节点，可通过参数调整。节点数限制不保证避免 OOM；大规则集也会占用内存。是否使用 Swap 应结合内存、存储介质和写入寿命判断。

临时传输和运行缓存使用 `/tmp`，网络恢复快照和启动钩子写入 `/etc`。持久化恢复会产生闪存写入，不应描述为零写入。

## DNS、旁路由与 IPv6

代理节点域名需要真实地址解析，不能把引导解析器指向 FakeIP。部署前运行配置检查器，再检查设备上的实际 DNS 请求路径。FakeIP 答案、空答案或诊断脚本返回成功均不能单独证明无泄漏。

旁路由使用 `--bypass` 配置 NAT；还需核对终端网关、回程路由和上游设置。`filter_aaaa=1` 会过滤 AAAA 答案，不能代替完整 IPv6 路由配置；需要保留双栈时使用 `--keep-ipv6` 并验证两条路径。

## 凭据与发布

使用凭据管理器或 SSH Agent 保存认证信息。不要提交私钥、真实节点、订阅地址、路由器备份和未脱敏日志。`.gitignore` 不会移除已跟踪文件；发布前检查实际提交和压缩包。`git archive` 排除 `.git`，但仍会包含提交中的敏感内容。

## 测试结论

Mock 只覆盖有限命令响应，不证明真实防火墙、eBPF 或网络转发正常。原生语法校验、服务启动、局部转发和完整客户端业务是不同的验证范围。未执行或被环境阻塞的项目应分别记录，不计为通过。
