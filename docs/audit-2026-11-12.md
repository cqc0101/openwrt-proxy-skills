## 修复后的兼容性与使用边界

- 订阅下载不再采用环境中的 HTTP/HTTPS 代理。代理可能自行解析域名，破坏“批准哪个地址，就连接哪个地址”的边界。当前下载始终直连批准的地址，不会静默借助代理重试。
- `allow_private` 的语义收紧。普通内网订阅仍可用该选项；更小权限应使用精确 host:port 白名单。169.254.0.0/16、AWS IPv6 IMDS、阿里云元数据地址及 Azure 平台地址被固定拒绝。本功能不改变系统 DNS、系统防火墙或平台服务的其他访问。
- 新版持锁身份是“实例令牌 + PID + owner/task”，重新构造同 owner/task 的对象不能接管存活实例。升级前先结束旧写任务，禁止新旧锁协议混用。旁路 `.guard` 文件必须保留；这些锁要求同一台宿主机、本地可信文件系统以及所有写入方共同遵守协议。
- `ApprovalToken` 是当前 Python 进程内的内存对象，线程锁不构成跨进程或跨主机的一次性授权存储。不能把令牌复制到多个进程后宣称全局单次消耗，也不能把可变的 Python 对象当作不可信客户端凭据。
- 事务模块负责本地文件和传入的状态对象。真实设备的 sysctl、服务状态、原生引擎和业务健康仍需调用方实际采集及执行；Mock 不能证明真实网络转发、eBPF 或远端回滚成功。
- 静态 dae 检查不是上游完整语法解析器。请求局部 HTTP 传输使用 CPython 的连接实例扩展点，未来升级 Python 时应保留 HTTP、HTTPS、SNI 和证书回归测试。
- 既有历史硬件验证记录仅代表原包的历史声明，本轮没有重新验证；不能据其推导本次修订已通过所有硬件、内核和上游版本测试。

## 原报告“安全亮点”的复核说明

SHA-256 备份校验、计划哈希、逐跳重定向、解压大小限制和默认 TLS 校验都在代码中存在，并有自动测试。它们不能证明所有使用路径均安全：原 DNS 实现有并发状态问题，原 SSH 数组没有保护远端 Shell，原日志恢复及清单加载也有缺陷。状态转换图实际包含 17 个状态名，而模块和历史文档多处称“15 状态”；属于文案不准确，不影响已测试的转换关系。保留历史版本记录，但本次按实际图核验，没有把文档中的星级评价作为安全证据。

## 关键技术依据

OpenSSH 明确说明会把多个远端参数以空格拼接后发送，因此本地参数数组不能替代远端 Shell 转义。[OpenSSH ssh(1)](https://man.openbsd.org/ssh.1)

Windows 下 CPython 对控制台事件采用 `GenerateConsoleCtrlEvent`，该语义不同于 POSIX 的信号 0 存活查询。[CPython 3.14.2 源码](https://github.com/python/cpython/blob/v3.14.2/Modules/posixmodule.c)

OS 锁分别依据 [Python flock 接口](https://docs.python.org/3.14/library/fcntl.html) 与 [Windows 字节范围锁接口](https://docs.python.org/3.14/library/msvcrt.html)。HTTPS 默认执行证书与主机名校验，连接改造保留此行为。[Python HTTPSConnection](https://docs.python.org/3.13/library/http.client.html)

AWS 元数据支持 IPv4 和 IPv6 两个端点，阿里云使用 CGNAT 范围中的专用地址，Azure 的平台地址具有特殊用途；因此仅排除 RFC1918 并不足够。[AWS IMDS](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/instancedata-data-retrieval.html)、[阿里云元数据](https://www.alibabacloud.com/help/en/ens/instance-metadata)、[Azure 平台地址](https://learn.microsoft.com/en-us/azure/virtual-network/what-is-ip-address-168-63-129-16)
