# R2S 真机测试计划

测试对象：当前已审计 Git 提交 e4b639a5f7f924fe566724c544462d3e14233e83。设备登录凭据与完整配置仅保存在私有工作区。

## 轮次与门禁

1. 只读探测、完整文件清单、静态审计、依赖核验；先完成本计划。已获得设备 /etc 完整备份并核对远端与本机 SHA-256。
2. 逐脚本正常/错误参数、空输入、路径和字符边界测试。命令、输入、输出、退出码、耗时写入证据。
3. 两个引擎分别使用原生校验器验证生成配置，在私有临时目录启动受控实例。先验证缺失依赖，不以安装不匹配的内核包规避失败。
4. 网络接管前建立独立于项目的恢复脚本与计时器；保持管理口 eth0 地址不变。实测防火墙、DNS、转发、幂等性，并比较恢复后的文件和运行状态。
5. 仅以本机/路由器上的受控服务执行 SSRF、重定向、注入、符号链接、并发、进程中断等测试。压力限制：单轮不超过 20 秒、内存不超过 64 MiB、临时文件不超过 16 MiB；不用 Flash 耗尽。
6. 故障部署、原生语法失败、服务失败、watchdog 超时、SSH 中断、备份损坏与恢复失败；必须核验恢复结果。
7. 保存失败现场后修复；全量回归；复测受影响真机案例；清理测试状态，生成 15 份报告、证据索引与修复包。

## 当前设备与边界

NanoPi R2S；ImmortalWrt 25.12.2；Linux 6.12.103；aarch64；约 1 GiB 内存。管理地址位于 eth0 WAN，默认网关为上级路由。br-lan/eth1 无载波，DHCP 租约为空，当前没有活跃的物理 LAN 测试客户端。原生 dae 2.1.1 正在运行，sing-box 未安装，/dev/net/tun 尚不存在，Python 未安装，使用 apk。BTF 存在，防火墙为 fw4/nftables。

已观察到历史 dae 日志包含客户端流量；正式切换服务前需要再次确认当前连接和租约，若出现未经授权的其他设备业务，停止相关接管测试。

## 判定规则

PASS 需要配置、进程与实际行为证据，不能只看返回码。FAIL 保存原始现场及复现输入。环境缺失为 BLOCKED，未执行为 NOT TESTED，证据不足为 INCONCLUSIVE。一台 ARM64 真机不能证明其他固件、架构、fw3、双栈或重启恢复兼容性。先核验独立恢复，再考虑重启；没有可验证的启动恢复路径则不执行重启故障测试。
