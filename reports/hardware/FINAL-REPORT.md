# R2S 真机审计与修复报告

本轮已完成可行的设备测试与修复，但不能认定完整 LAN 透明代理和 DNS 无泄漏验证完成。TUN、物理 LAN 客户端、公网 IPv6 和设备 Python 缺项已分别标记，不将正常返回码当作业务通过。

本报告只针对本轮实际设备与当前修订代码。原始 /etc 备份、SSH 主机密钥、真实节点与订阅均留在私有工作区，不进入修复包。公开证据已脱敏；原始命令、输入和完整输出仍保存在本机私有证据目录。执行过程先完成探测与计划，再按轮次进行受控测试，未修改固件、分区或 Bootloader。


## 环境

FriendlyElec NanoPi R2S，ImmortalWrt 25.12.2 r38135-0c4cd0f9920a，Linux 6.12.103，aarch64_generic，约 1 GiB RAM；根 ext4 约 290 MiB、基线可用约 181 MiB，/tmp 约 488 MiB。原生 dae 2.1.1 常驻，sing-box 1.14.4 ARM64 musl 临时运行。管理口为 WAN eth0，br-lan/eth1 无载波；184 个软件包。

## 规模与结果

源文件 98（基线 97、新增行为测试 1）；Python 38、Shell 9。硬件台账 72 项，实际执行 59，PASS 55、FAIL 3、BLOCKED 4、NOT TESTED 9、INCONCLUSIVE 1。三个 FAIL 保留原版缺陷复现，修订版对应复测通过；不是最终代码仍有这三项失败。

自动回归 348 个独立用例：最终源树 Linux 348 通过、0 跳过；Windows 中间修订 343 通过、5 跳过（Linux 专属与可选依赖），最后服务状态防护和消息收敛以最终 Linux 全量回归为准。日志见 evidence。早期两 vCPU 仿真出现进程启动 20 秒超时，另有 lo 未启用导致本机服务器绑定失败；修正仿真环境并分配足够 vCPU 后重跑，没有放宽断言或修改超时时间来取得通过。诊断注册契约缺失也被全量回归发现并补齐。

修复过程中另发现并修正：使用 stat 会在该精简固件失败；新增诊断 ID 初次未同步修复注册表。两次失败均在交付前被实际测试发现，最终回归重新执行。未把早期失败日志当作最终通过证据。

发布目录检查另发现：新增 reports 目录后 README 目录树漏写该项，导致首次硬件报告提交的三组 CI 均在结构一致性检查失败。已补齐目录与真机验证入口，并对包含报告的完整发布目录重新执行检查；未删除或放宽原断言。


## 恢复

完整文件快照、私有令牌与设备锁已替代危险 PID 路径；防火墙失败/备份损坏会阻断并保留证据。手动回滚、SSH 关闭后的 watchdog、真实重启恢复均有证据。最终全部 176 个 /etc 普通文件内容与初始归档相同，原始 dae 配置和服务恢复，SSH/DNS 正常。细节与不能证明的范围见 recovery-test-report.md、before-after-diff.md。

## 兼容性与剩余工作

只对本机 ARM64/fw4 的已执行路径给出真机结论。sing-box 本机 TCP 转发和回环 API 边界通过；TUN 因缺 /dev/net/tun 启动失败。dae 原生校验/重载通过，但未证明实际 LAN 透明转发、外网节点业务或重载长连接零中断。其他固件/架构/fw3、TProxy、真实 OOM、上传/Agent 中断等见台账。现有部分 dae 节点在运行时被拒绝，未更改真实节点；现有 WAN 输入 ACCEPT 与独立 dnsmasq DNS redirect 需生产部署时单独处理。

本报告记录已确认的问题、修复证据和测试范围，不对项目质量作主观分数评价。测试受设备与网络条件限制的部分已列入未测项。
